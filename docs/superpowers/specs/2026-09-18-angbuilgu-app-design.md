# 휴대용 앙부일구 앱 설계

작성일: 2026-09-18

## 1. 목적

조선의 휴대용 앙부일구를 휴대폰에서 실제로 작동하는 해시계로 되살린다. 사용자는 휴대폰을 눕히고 남북을 맞춘다. 화면 속 반구에 그림자가 떨어지고, 그 그림자가 가리키는 시각을 읽는다.

앱의 성격은 박물관 전시물이 아니라 도구다. 지금 이 자리에서 시각을 읽는 물건으로 만든다. 원리와 역사는 툴팁과 도움말로 전한다.

## 2. 역사적 근거

보물 852호 휴대용 앙부일구를 기준 유물로 삼는다. 확인한 사실은 다음과 같다.

| 항목 | 값 |
| --- | --- |
| 제작 | 강건(姜湕), 1871년(고종 8) |
| 재질 | 대리석 계열 석재 |
| 크기 | 5.6 × 3.3 × 1.6 센티미터 |
| 시반 지름 | 2.8 센티미터 |
| 나침반 지름 | 1.9~2.0 센티미터 |
| 소장 | 국립중앙박물관 |
| 측면 명문 | 北極高 三十七度 三十九分 一十五秒 |

시반에는 30분 간격 시각선과 절기선 13개를 음각하고 채색했다. 시각 체계는 시헌력 96각법이다. 영침은 청동이며 끝이 반구 중심에 놓이고 천구 북극을 향한다.

다음 두 가지는 흔히 잘못 알려져 있으므로 앱의 설명문에서 쓰지 않는다.

- 제작 연도를 1881년으로 적는 자료가 있으나 1871년이 맞다. 1881년은 형 강윤이 만든 다른 해시계의 연도다.
- 재질을 상아로 적는 자료가 있으나 852호는 석재다. 상아제는 강윤 등이 만든 별개의 유물이다.

뒷면의 24절기별 일출입 시각표는 어느 자료에서도 확인되지 않았다. 앱에 넣지 않는다.

## 3. 범위

### 첫 버전에 넣는 것

- 위치와 시각으로 그림자를 그리는 실시간 해시계
- 나침반으로 남북을 맞추는 물리적 정렬
- 사용자 위도에 맞춘 눈금 생성과 한양 원본 눈금 전환
- 전통 시각, 진태양시, 표준시 세 가지 표시
- 밤에는 달시계 모드, 설정으로 대기 화면 방식 전환
- 눈금과 용어를 누르면 뜨는 툴팁, 도움말 화면, 절기별 그림자 변화 애니메이션
- 위성 신호를 못 받거나 권한을 거부했을 때 쓰는 수동 위치 입력
- 한국어, 아이폰과 안드로이드

### 첫 버전에서 빼는 것

- 증강현실 카메라 모드
- 알림과 위젯
- 날짜와 시각을 돌려 보는 탐색 슬라이더
- 다국어
- 계정과 서버. 모든 계산을 기기 안에서 한다

## 4. 구조

네 층으로 나눈다. 아래층은 순수 계산이고 위층은 센서와 화면에 닿는다.

**천문 계산층.** 위도, 경도, 시각을 받아 태양과 달의 고도, 방위, 적위, 시간각, 균시차를 낸다. 리액트 네이티브에 의존하지 않는다.

**눈금 기하층.** 위도를 받아 절기선과 시각선의 경로를 만든다. 태양의 고도와 방위를 받아 그림자 끝의 위치를 낸다. 이 층도 순수 계산이다.

**배치층.** 나침반 방위와 기울기를 읽어 회전값 하나로 바꾼다. 반구를 지면에 어떻게 놓았는지를 나타낸다.

**화면층.** 위 세 층의 결과를 스킨으로 그리고 툴팁과 설정을 붙인다.

### 회전값 하나로 자세를 표현한다

그림자 끝의 방향은 언제나 태양의 정반대다. 이것을 세상 기준으로 구한 뒤 회전값을 곱하면 반구 기준의 방향이 나온다.

```
그림자 방향(세상) = -태양 방향
그림자 방향(반구) = 회전값 × 그림자 방향(세상)
화면 좌표      = 정사영(그림자 방향(반구))
```

눕힌 모드에서는 회전값이 나침반 방위 하나로 정해진다. 세운 모드를 나중에 넣으면 같은 자리에 기울기까지 포함한 회전값을 넣는다. 그리는 코드는 바뀌지 않는다.

## 5. 좌표계와 기하

### 좌표계

세상 좌표는 동쪽, 북쪽, 천정을 세 축으로 삼는다. 방위는 북에서 시계 방향으로 잰다.

```
태양 단위벡터 s = (cos h · sin A,  cos h · cos A,  sin h)
그림자 방향    u = -s
```

반구는 중심이 원점인 구의 아래쪽 절반이다. 영침 끝이 원점에 있다. 그림자 끝은 원점에서 u 방향으로 반지름만큼 나간 점이다.

### 정사영

위에서 내려다본 평면에 옮긴다. 화면 위쪽이 반구의 북쪽이다.

```
화면 X = 반지름 × u'x
화면 Y = -반지름 × u'y
```

그림자 끝까지의 거리는 태양 고도의 코사인에 비례한다. 해가 뜰 때는 가장자리에 있고 높이 뜰수록 중심으로 온다.

### 영침

영침은 정남쪽 자오선을 따라 북극고도만큼 내려간 점에서 원점까지 뻗는다. 반구 좌표로는 다음과 같다.

```
영침 뿌리 = 반지름 × (0, -cos φ, -sin φ)
```

화면에서는 중심에서 남쪽으로 내려간 자리에 놓인다.

### 절기선

극축을 중심으로 한 작은 원이다. 극에서 떨어진 각도는 90도에서 그날 태양 적위를 뺀 값이다. 동지선이 가장 크고 하지선이 가장 작다. 13개를 그리며, 동지와 하지만 단독이고 나머지 22개 절기는 적위가 같은 것끼리 선을 공유한다.

| 공유하는 절기 쌍 |
| --- |
| 춘분과 추분, 청명과 백로, 곡우와 처서, 입하와 입추, 소만과 대서, 망종과 소서 |
| 경칩과 한로, 우수와 상강, 입춘과 입동, 대한과 소설, 소한과 대설 |

각 절기선은 그날 해가 뜨는 시간각부터 지는 시간각까지 그린다. 여름에는 해가 오전 5시 전에 뜨므로 절기선이 가장 바깥 시각선을 넘어간다. 넘어간 부분은 옅게 그려 눈금이 없는 구간임을 보인다.

### 시각선

극축을 품은 큰 원의 조각이다. 모든 시각선이 영침 뿌리 한 점에서 모인다. 시간각 범위는 오전 5시부터 오후 7시까지, 곧 좌우 105도다. 30분 간격으로 29개를 그린다.

이 중 7개를 주선으로 굵게 긋고 묘, 진, 사, 오, 미, 신, 유를 새긴다. 주선은 각 시의 정에 놓이며 6시, 8시, 10시, 12시, 14시, 16시, 18시에 해당한다. 나머지는 보조선이다.

라벨을 초와 정 중 어느 쪽에 새겼는지는 유물 사진으로 최종 확인한다. 확인 전까지는 위 배치를 쓴다.

### 검산

한양 위도로 계산한 값을 2010년 김천휘 외 논문의 도면 수치와 맞추어 보았다.

| 항목 | 계산값 | 논문값 |
| --- | --- | --- |
| 남쪽 가장자리에서 영침 뿌리까지 | 지름의 0.1045 | 0.104 |
| 남쪽 가장자리에서 하지선까지 | 지름의 0.6227 | 0.623 |
| 남쪽 가장자리에서 동지선까지 | 지름의 0.9376 | 0.938 |

세 값이 소수점 셋째 자리까지 맞는다. 이 수치를 회귀 테스트의 기준값으로 삼는다.

### 눈금을 다시 만드는 시점

위도가 일정 이상 변했을 때만 다시 계산한다. 몇 킬로미터 이동으로는 다시 그리지 않는다. 한양 원본 눈금으로 전환하면 위도를 37도 39분 15초로 고정한다.

## 6. 시각 체계와 변환

### 96각법

하루를 12시로 나눈다. 각 시는 두 시간이며 앞의 한 시간이 초, 뒤의 한 시간이 정이다. 각 한 시간을 15분짜리 각 넷으로 나눈다. 자시가 밤 11시에 시작하므로 오정초각이 정오다.

```
진태양시 12:00  →  오정 초각
진태양시 12:40  →  오정 2각
진태양시 15:20  →  신초 1각
```

### 세 가지 시각

그림자가 직접 가리키는 것은 진태양시다. 균시차를 빼면 평균태양시가 되고, 경도 차이를 더하면 표준시가 된다.

```
표준시 = 진태양시 - 균시차 + (135도 - 관측지 경도) × 4분
균시차 = 진태양시 - 평균태양시
```

식의 135도는 한국 표준시의 기준 경도다. 기기의 시간대에서 기준 경도를 가져와 쓰므로 다른 시간대에서도 맞는다.

서울은 기준선보다 서쪽에 있어 32분가량 차이가 난다. 균시차는 계절에 따라 앞뒤로 움직인다. 두 보정값을 각각 툴팁으로 설명한다.

### 표시 순서

전통 시각을 가장 크게 놓는다. 이 앱의 주인공이기 때문이다. 진태양시와 표준시를 그 아래에 작게 둔다. 사용자가 자기 시계와 비교하는 순간 답이 바로 옆에 있게 한다.

## 7. 달시계

### 보름달을 기준으로 삼는다

보름달은 태양의 정반대에 있으므로 자정에 남중한다. 보름달 그림자는 태양 그림자와 정확히 12시간 어긋난 자리에 떨어진다. 눈금이 오정을 가리키면 실제로는 자정이다.

보름달의 적위는 그날 태양 적위와 거의 반대다. 하짓날 보름달은 겨울 해처럼 낮게 지나가므로 그림자가 동지선 근처에 떨어진다. 절기선 13개가 덮는 범위 안에 머문다.

### 보정

보름에서 하루 멀어질 때마다 약 50분씩 벌어진다. 앱은 이 어림셈이 아니라 달의 실제 위치로 보정값을 구한다. 화면에는 어림셈도 함께 적어, 옛 규칙이 왜 통했는지 보이게 한다.

| 표시 항목 | 예시 |
| --- | --- |
| 눈금이 가리키는 값 | 오정 초각 |
| 12시간 뒤집은 값 | 자정 |
| 보름에서 지난 날수 | 3일 |
| 보정한 실제 시각 | 오전 2시 30분 |

반구에 새겨진 글자는 유물 그대로 둔다. 뒤집기와 보정은 아래 읽기 영역에서만 한다.

### 두 가지 예외 상태

- 달빛이 약하면 그림자가 실제로 생기지 않는다. 밝기 비율과 고도를 함께 보고 판단해 달 모양과 함께 알린다. 임계값은 실제 관측으로 조정한다.
- 달의 적위는 태양보다 남북으로 넓게 움직인다. 보름에서 멀어지면 그림자가 절기선 바깥으로 나간다. 반구 안에 그리되 절기선 밖이라는 것을 표시한다.

### 설정

기본은 낮에는 해, 밤에는 달이다. 다른 하나는 해만 쓰고 밤에는 일출까지 남은 시간을 보여 주는 방식이다. 달시계를 나중에 유료로 분리하려면 이 설정 지점이 그대로 경계가 된다.

## 8. 센서와 정렬

### 방위

엑스포 위치 모듈에서 진북 값을 받는다. 안드로이드에서 값이 준비되지 않으면 자북 값에 편각을 더해 쓴다. 원형 평활 필터를 거쳐 떨림을 없앤다. 나침반 정확도가 낮으면 팔자로 흔들어 보정하라고 안내한다.

### 수평

중력 방향으로 판정한다. 기울기가 임계값을 넘으면 수평계를 띄운다.

### 갱신 주기

천문 계산은 초당 한 번이면 충분하다. 화면 회전만 센서 속도로 따라간다. 화면이 꺼지면 센서 구독을 끊는다.

### 정렬 경험

휴대폰을 돌리면 그림자가 눈금 위를 미끄러진다. 실물 앙부일구를 돌릴 때와 같다. 방위가 어긋나 있으면 반구 둘레의 고리가 어느 쪽으로 돌릴지 알려 준다. 북쪽에 가까워질수록 빛이 모인다. 방위와 수평이 모두 맞으면 안내가 사라지고 눈금만 남는다.

### 임계값

구현을 막지 않도록 시작값을 정해 둔다. 실제 기기로 확인하며 조정한다.

| 항목 | 시작값 |
| --- | --- |
| 정렬로 인정하는 방위 오차 | 3도 |
| 수평으로 인정하는 기울기 | 5도 |
| 눈금을 다시 만드는 위도 변화 | 0.05도 |
| 나침반 보정을 권하는 정확도 | 시스템이 낮음 이하로 보고할 때 |
| 달그림자가 생긴다고 보는 밝기 | 밝은 면 비율 0.5 이상이면서 고도 10도 이상 |

## 9. 화면과 디자인

### 구성

한 화면에 담는다. 반구가 대부분을 차지하고 위에는 날짜와 절기, 아래에는 시각 읽기를 놓는다. 설정과 도움말은 아이콘으로 접는다.

반구 바깥의 하늘에 해와 달을 실제 방위와 고도에 맞추어 띄운다. 그림자가 왜 저쪽으로 뻗는지가 한눈에 들어온다.

### 사용성 원칙

쉽고 아기자기한 앱으로 만든다. 사용자가 천문학을 몰라도 즐겁게 쓰게 한다.

- 첫 화면에서 할 일은 하나다. 휴대폰을 눕히고 돌려서 맞추는 것이다. 다른 요구를 앞세우지 않는다.
- 어려운 말 앞에 쉬운 말을 둔다. 큰 글씨는 "지금은 낮 12시 15분", 작은 글씨는 "오정 초각"으로 적는다.
- 설명은 사용자가 궁금해하는 자리에 둔다. 긴 도움말을 먼저 읽게 하지 않는다.
- 정렬이 어긋나도 막지 않는다. 그림자는 계속 보이고, 맞출수록 화면이 반응한다.
- 실패 상태에서도 앱이 멈추지 않는다. 위치나 나침반이 없어도 볼 것이 남는다.

원리를 가르치려 들지 않는다. 손으로 돌려 맞추는 동안 저절로 알게 한다.

### 시각 방향

유물의 질감을 바탕에 깔고 빛을 주인공으로 쓴다. 동화적이고 몽환적이면서 아기자기한 화면을 목표로 한다. 근엄한 유물이 아니라 손안의 작고 예쁜 물건으로 느껴지게 한다.

- 낮에는 따뜻한 돌빛이다. 그릇 안쪽에 햇빛이 번지고 그림자 끝에 작은 빛무리가 맺힌다.
- 밤에는 푸른 달빛이다. 하늘에 별이 옅게 깔리고 음각이 달빛을 머금는다.
- 해 뜨고 지는 시각에 맞추어 배경이 천천히 물든다.
- 그림자는 끊기지 않고 미끄러진다. 정렬되는 순간에 빛이 한 번 번진다.

### 읽기가 먼저다

눈금선과 글자는 항상 배경보다 또렷하게 유지한다. 장식하는 빛은 눈금 뒤로 물러난다. 밝은 햇빛 아래 야외에서도 읽히도록 대비를 확보한다. 분위기가 가독성을 이기지 않게 한다.

## 10. 기술 선택

| 항목 | 선택 |
| --- | --- |
| 프레임워크 | 엑스포 SDK 57, 리액트 네이티브 0.86 |
| 화면 그리기 | 스킨 |
| 움직임 | 리애니메이티드 |
| 위치와 방위 | 엑스포 위치 모듈 |
| 기울기 | 엑스포 센서 모듈 |
| 태양과 달 위치 | 직접 구현 |
| 적위와 균시차 | 직접 구현 |
| 정확도 검증 | astronomy-engine, 개발 의존성으로만 사용 |
| 테스트 | 엑스포 제스트 프리셋 |

태양과 달의 위치를 직접 구현한다. 눈금을 그리려면 적위와 균시차가 반드시 필요한데 기존 라이브러리가 이 값을 내보내지 않는다. 계산식 자체는 짧고, 직접 두면 계산층에 바깥 의존성이 하나도 남지 않는다. 정확도는 astronomy-engine을 기준 삼아 테스트로 지킨다. 태양은 0.15도, 달은 0.5도 안쪽이다.

`src/lib` 아래는 리액트를 쓰지 않는다. 함수만 내보내고 테스트로 전부 덮는다. 폴더 이름은 엑스포가 권하는 방식을 따라 소문자와 붙임표로 쓴다.

## 12. 테스트

- 천문 계산은 astronomy-engine의 값과 맞춘다. 허용 오차는 0.15도로 잡는다.
- 눈금 기하는 5절에 적은 세 수치를 기준값으로 회귀 테스트한다.
- 96각법 변환은 경계값을 전부 확인한다. 자시의 날짜 넘김, 각의 경계, 정오와 자정을 포함한다.
- 표준시 변환은 균시차가 가장 큰 날과 0이 되는 날로 확인한다.
- 배치층은 방위값을 넣어 그림자 화면 좌표가 기대한 자리에 오는지 확인한다.

정확도 목표는 태양 고도와 방위 0.1도 이내, 표시 시각 1분 이내다.

## 13. 예외 상태

| 상황 | 동작 |
| --- | --- |
| 위치 권한 거부 | 수동 위치 입력으로 넘긴다 |
| 위성 신호 없음 | 마지막 위치를 쓰고 알린다 |
| 나침반 없음 | 정렬된 상태로 가정해 그림자를 그리고, 정렬을 확인할 수 없다고 알린다. 표시 시각은 계산값이므로 정확하다 |
| 나침반 부정확 | 보정 안내를 띄운다 |
| 휴대폰이 기울어짐 | 수평계를 띄운다 |
| 위도 66도 이상 | 백야와 극야로 눈금이 성립하지 않음을 알린다 |
| 위도 0도 이하 | 첫 버전은 북반구만 지원한다고 알린다 |

지원하는 위도는 0도 초과 66도 미만이다.
